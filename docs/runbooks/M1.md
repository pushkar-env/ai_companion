### Reproduce local diagnostics

### Build the portrait Android character diagnostic

Run `./tools/build-android-test.ps1` from the repository root. It snapshots source under
`artifacts/android-test/<timestamp>/project`, then runs the pinned Editor in hidden batch
mode for Android. Main Editor target, windows/layout and scene list are not changed.
Requires Unity 6000.5.9f1 Android Build Support, SDK/NDK/OpenJDK and a valid local Unity
license. A fresh import may take several minutes. Inspect `unity-build.log` if it fails.
The runner requires 20 GiB free on workspace/temp volumes before copying; this is a
minimum preflight, not a peak-space guarantee. It never cleans up files automatically.

Output is `output/Companion-CC-Test.apk`: development-only, ARM64 IL2CPP, local debug key,
test ID `com.local.aicompanion.cctest`, portrait-only. It is not a release or store build.
`tools/verify-android-apk.ps1 -Apk <path>` inspects the packaged manifest and native library.
Success is recorded only when both the Unity build and package checks finish successfully.
The CC diagnostic build now retains only its 30 exercised native facial controls in
temporary mesh copies. The full source/editor rig is preserved. Run **Companion > Check
CC Build Mesh Subset** to compare all retained frames and geometry before a build.
This does not reduce triangles/material slots or certify production facial coverage.

Before device installation, connect/authorize the S23 for USB debugging and verify ADB
visibility. This does not authorize replacing another app's data or factory resets.
After install, test rotation lock, face preview, scrollable controls, reset, synthetic
audio/end/interruption and background/resume. Record OS/build/network and any issues.
The app uses no microphone or provider; do not claim native voice validation from it.
The main Editor's Game-view selection is user-controlled; portrait preview menu is optional.

Open `Assets/Companion/Scenes/FacialDiagnostics.unity` with the Companion menu, enter
Play Mode and run **Companion → Run M1 Synthetic Play Mode Checks**. The test bakes the
mesh to confirm each of 52 channels changes exactly its pad vertices, then exercises
the audio sample clock, interrupt/late-frame rejection, completion, simulated lifecycle
callbacks and repeated sessions. Callback simulation cannot validate native device events.
Binding validation checks names/weights only; it does not certify anatomy, rigging or rights.
Production assets remain unavailable under Q-010; no production voice is selected.

Both Android and iOS physical IL2CPP builds must demonstrate permissions, routing and
